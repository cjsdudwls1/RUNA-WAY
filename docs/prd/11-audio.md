# 오디오 안내 설계

## 문제

- 러너는 숨이 차서 화면을 못 본다. 어디서, 얼마나 빨리, 몇 미터인지 귀로 알아야 한다
- 그렇다고 계속 말하면 두 번째 세션부터 음소거당한다

## 원칙

정보를 두 채널로 나눈다. 섞으면 둘 다 망한다.

| 채널 | 담는 정보 | 이유 |
|---|---|---|
| 비언어 (동물 소리) | 방향, 거리, 상태 | 연속 정보. 말로 하면 끝없이 떠들어야 한다 |
| 언어 (음성) | 사건, 행동을 바꿔야 하는 순간 | 이산 정보. 드물어야 무게가 있다 |

핵심 문장: 말은 소리를 읽는 법을 가르치는 역할만 한다. 다 배우면 물러난다.

## 비언어 채널

방향

- 좌우: HRTF 입체 음향 + 스테레오 강조(`sin(상대방위) x 0.55`). 실측 좌우 귀 차이 약 15dB, 여기에 좌우 시간차가 더해진다 (2026-09-25 방향감 약하다는 피드백으로 0.35에서 올림)
- 앞뒤: 음색. 뒤쪽은 로우패스를 45% 더 건다. 사람 귀가 실제로 뒤를 둔탁하게 듣는다
- 이어폰 없이 스피커면 좌우가 안 들린다
- HRTF 채택 (2026-09-24, 이전 결정 뒤집음)
  - 이전 판단: 크롬 HRTF는 평균 머리 모델이라 앞뒤 단서가 약하고 비용이 약 20배
  - 앞뒤가 약한 건 맞다. 앞뒤는 계속 음색으로 준다
  - 비용 실측: 소리 6개를 계속 틀어도 실시간 대비 CPU 1.3% (스테레오 0.27%, 약 5배). 실제 게임은 동시에 1~3개
  - 얻는 것: 소리가 머리 안이 아니라 밖에서 난다. 실제 녹음을 쓰면서 차이가 커졌다
  - HRTF만으로는 좌우 차이가 실제 귀 수준(약 6dB)이라 달리면서 듣기엔 약해 스테레오 강조를 더했다

야외 가청성

- 정보를 지는 단서는 800 Hz~3 kHz에 있어야 한다. 바람소리와 차소리가 저역을 통째로 덮는다
- 개과, 발굽, 고양이과의 울음은 저역에 몰려 있어 밖에서 안 들릴 위험이 있다
- 울음마다 1.8 kHz 대역통과 온셋을 얹었다. 동물 소리의 성격은 그대로 두고 들리는 시작점만 준다

거리

- 2026-09-25 재설계. 예전 곡선은 100m에서 600Hz까지 깎아 무슨 소리인지 뭉개졌고, 감지 반경+50m 밖에선 아예 무음이었다
- 거리 척도: `near = 1 - log2(거리/8m)/6`. 8m=1, 64m=0.5, 512m=0. 두 배 멀어질 때마다 같은 만큼 변한다
- 음량: `(8/거리)^0.8`. 실측 두 배마다 약 5dB (16→32→64→128→256m: 5.1/4.9/5.4/5.5dB). 512m까지 끊기지 않는다
- 밝기: 로우패스 `16000 x (8/거리)^0.45` Hz. 16m 11.7kHz, 64m 6.3kHz, 256m 3.4kHz
- 울음 주기 상한 3초. 멀어도 3초 넘게 조용하지 않는다(예전엔 12~20초 침묵)
- 음량: `near^1.5` (옛 값)
- 밝기: 로우패스 컷오프 `300 + 5000 x near^2` Hz (옛 값)
- 잔향: 직접음보다 천천히 준다. 보내는 양 `0.45 x near^0.2 x (1 - 0.6 x near)`. 실측 직접음/잔향 12m +20dB, 64m +4dB, 275m -6dB. 야외라 짧고 어둡게(25ms 뒤 시작, 1.4초 감쇠, 3kHz 이하)
  - 멀리서 난 소리는 직접음보다 주변에 튄 소리가 더 많이 들린다. 사람이 "멀다"를 느끼는 가장 큰 단서다

| 거리 (near) | 직접음 | 직접음/잔향 |
|---|---|---|
| 가까이 (0.9) | 기준 | +15dB, 또렷함 |
| 중간 (0.5) | -10dB | +7dB |
| 멀리 (0.15) | -30dB | -6dB, 울림이 더 큼 |

- 측정: web/qa.mjs 8번. 앱의 출력 체인을 그대로 꺼내 오프라인 렌더링으로 귀별 에너지를 잰다
- 울음 주기: 이게 진짜 거리계다. 주차 센서와 같은 원리

계단이 아니라 기하 곡선. 주차 센서와 가이거 카운터가 쓰는 법칙이다.

`주기(초) = clamp(0.45 x (거리m / 30)^1.35 x k, 0.34, 12)`
k는 스프린트 0.7, 지침 1.7, 배회 1.0. 회복 12초 고정, 워밍업 20초 고정.

| 거리 | 배회 | 스프린트 |
|---|---|---|
| 300 m | 10.1초 | 7.1초 |
| 200 m | 5.8초 | 4.1초 |
| 120 m | 2.9초 | 2.1초 |
| 80 m | 1.7초 | 1.2초 |
| 50 m | 0.9초 | 초당 2회 |
| 30 m | 0.45초 | 초당 3회 |
| 15 m | 초당 3회 | 초당 3회 |

30 m는 위협 게이지가 차기 시작하는 반경이다. 거기서 소리가 거의 안 끊긴다.
"안 끊기면 게이지가 차는 중"을 귀로 배우게 되고, 그때부터 화면을 볼 이유가 없어진다.
50 m는 게이지가 멈추는 반경. 소리가 초당 2회에서 끊기기 시작하면 벗어난 것이다.

## 실제 녹음 (2026-09-24)

- 합성음 대신 실제 동물 녹음을 쓸 수 있다. 규격은 web/sounds/README.md
- 동물별 파일 → 동물군 공용 파일 → 합성음 순으로 대체한다
- 같은 상태에 녹음이 여럿이면 직전 것과 다른 것을 고르고, 재생 속도를 ±3% 흔든다
- 녹음은 합성음보다 길다. 사건이 아닌 울음은 동시에 2개까지만. 돌진 시작·피격은 제한 없이
- 지침 녹음이 있으면 합성 숨소리를 겹치지 않는다

## 언어 채널

- 2026-09-24부터 관제 음성은 기본 끔. 사용자 판정: TTS 목소리가 마음에 안 든다. 설정 > 관제 음성에서 켤 수 있고 선택은 기억한다
- 끄면 음성 팩(2.8MB)도 받지 않는다


계단식 축소. 같은 사건이 반복될수록 짧아지고 결국 사라진다.

| 사건 | 1회 | 2회 | 3~4회 | 5회 이후 |
|---|---|---|---|---|
| 스프린트 시작 | "왼쪽 뒤에서 온다. 시속 40. 버텨!" | "또 온다. 왼쪽 뒤. 시속 40." | "온다. 왼쪽 뒤." | "왼쪽 뒤." (쿨다운 50초, 토큰 1) |
| 적 복귀 | "한 마리가 돌아왔다. 오른쪽 뒤 60미터." | 같음 | 소리만 | 소리만 |
| 적 지침 | "지쳤다. 헐떡인다. 지금이 기회다, 밟아!" | "지쳤다. 벌려!" | "헐떡인다. 지금이다." | "기회다." (쿨다운 120초, 토큰 1) |
| 피격 | "잡혔다. 1번째. 물러난다." | 같음 | 같음 | 같음 (항상 최우선) |

복귀와 스프린트를 둘 다 말하면 같은 말을 두 번 한다. 복귀는 3회부터 소리로만 알린다.

## 발화 제어

우선순위

- CRIT: 피격, 첫 접촉, 게이지 절반, 종료. 말하는 중이어도 끊고 나간다
- HIGH: 스프린트, 지침, 워밍업 경고
- NORM: 부연
- LOW: 분위기. `많이` 설정에서만

제한

- 최소 간격 3.5초. 겹쳐 말하지 않는다
- 키별 쿨다운. 같은 종류의 말은 정해진 시간 안에 다시 안 한다
- 유통기한 8초. 대기 중 낡은 정보는 버린다. 뒤늦게 "60미터"라고 말하지 않는다
- 토큰 버킷: 용량 3, 90초에 1개 충전. 중요한 말은 공짜, 부연은 토큰을 쓴다
- 문장 회전: 같은 키의 문장 후보를 돌아가며 쓴다. 연속 반복 없음

더킹

- 말할 때 동물 소리와 바람을 낮춘다. 묻히면 말한 의미가 없다

말 많음 3단계

- 적게: HIGH 이상만
- 보통: 기본
- 많이: LOW까지

## 진동

- 50 m 안에서 2초마다, 30 m 안에서는 3연타. 거리계의 보조 채널
- 화면이 꺼지면 진동은 죽는다. 정보 채널로 의존하면 안 된다
- 직접 경쟁작 Break A Leg는 진동을 주 채널로 쓴다. 음성도 공간 음향도 없다. 러너웨이의 해자는 오디오다

## 조사에서 잡힌 결함 (2026-09-13 반영)

3안 독립 설계와 적대적 검증에서 나온 지적. 전부 실재했다.

| 결함 | 왜 틀렸나 | 조치 |
|---|---|---|
| 지도 회전이 궤적 차분을 그대로 씀 | 폐기했다고 문서에 적고 렌더 경로에 살아 있었다. 소리와 지도가 서로 다른 방향을 쓰면 러너가 소리를 안 믿는다 | `st.headRad` 단일 소스로 |
| 패닝 `sin(rel) x 0.95` | 한쪽 귀에서 완전히 사라져 고장으로 들리고 도로 인지도 떨어진다 | 상한 0.7 |
| 뒤쪽 음량을 15% 깎음 | 추격 게임에서 뒤에서 오는 적이 더 조용하다. 규칙과 반대 | 뒤를 12% 키움 |
| 일시정지 중에도 비콘이 조여옴 | 게이지는 멈추는데 소리는 계속 조인다. "안 끊기면 차는 중"이 거짓이 된다 | 정지·쿨다운이면 주기 14초로 물러남 |
| 최근접 적 교체에 히스테리시스 없음 | 아무 사건 없이 상태 템포와 방향이 튄다 | 3m 이상 가까워야 교체 |
| 게이지 절반 경고가 세션당 1회 | 피격이 3회 가능한데 경고는 평생 한 번 | 게이지 20% 아래로 떨어지면 재무장 |
| 상시 진동 | 화면 꺼지면 죽는 채널이고 배터리와 습관화 양쪽에서 손해 | 30m 안 스프린트 중에만 |
| 마스터 리미터 없음 | 절차 합성이 겹치면 클리핑 | DynamicsCompressor -6dB |
| TTS가 "3마리"를 "삼마리"로 읽음 | 수 세는 말은 고유어여야 한다 | `numKo()` |
| 90초 무음이면 앱이 죽은 걸로 읽힘 | 침묵 설계가 "루즈하다"는 기존 피드백과 충돌 | 40초마다 아주 멀리서 울음 1회 |

## 아직 안 한 것

- 실제 동물 음원. 지금은 Web Audio 합성음
- HRTF 3D 패닝. 지금은 스테레오 + 음색으로 앞뒤 구분
- 진동 패턴의 방향 인코딩
- 스피커 모드 별도 설계 (패닝이 안 들리는 경우)
- 발소리 층. 적 속도를 보폭 템포로. 04-animal-data.md에 보폭 열이 없어 근거부터 필요하다
- 30m 안 연속 캐리어(그르렁). 지금은 초당 3회 펄스라 "끊김/안 끊김" 이분법이 덜 선명하다
- 탈출 가능성 계산 후 "N초만 버텨" 계약. 접근률은 2D라 `sp + player x cos(상대방위)`로 계산해야 한다
- 화면 끈 상태에서 오디오와 타이머가 실제로 사는지 실기 검증
