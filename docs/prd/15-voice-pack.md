# 신경망 음성 팩

- 14-voice-ai.md에서 채택한 "미리 구운 음성"의 구현
- 목표: 브라우저 기계음을 실감 나는 목소리로. 다급하게. 동물마다 다른 목소리. 비용 0

## 결론

- 관제사 1명 + 동물 25종 목소리를 미리 구워 앱과 같이 배포
- 런타임은 파일 재생만. 지연 0, 서버 0, 월 0원
- 팩을 못 받으면 기존 브라우저 TTS로 같은 문장을 읽는다. 말이 끊기는 일은 없다

## TTS 선택

| 후보 | 결과 |
|---|---|
| Edge 신경망 TTS (edge-tts, 무료 비공식) | 개발 환경 네트워크에서 차단. 약관상 앱 배포용으로도 회색지대 |
| Google 번역 TTS | 차단. 음질도 기계음 수준 |
| MeloTTS, MMS-TTS (허깅페이스) | 허깅페이스 차단 |
| Supertonic 3 (Supertone, 2026-04) | 채택. GitHub 릴리스(sherpa-onnx)로 받음. 한국어 포함 31개 언어, 음색 10종, CPU로 실시간의 2~3배 |

- 라이선스: 코드 MIT, 모델 OpenRAIL-M. 상업 이용 허용, 용도 제한 조항만 있음
- 배포하는 건 모델이 아니라 합성된 음성 파일. 모델 조항이 따라오지 않는다
- 앱 설정 화면에 출처 표기

## 구조

| 파일 | 역할 |
|---|---|
| web/voice/lines.py | 대사표. 관제사 조각, 동물 이름, 동물별 음색·피치·대사 |
| web/voice/bake.py | 굽기. 후보 생성 → 후처리 → ASR 역검증 → 선택 → 팩 |
| web/voice/qa.tsv | 조각별 오류율과 ASR이 들은 문장. 굽기 결과 기록 |
| web/static/voice/op.bin | 관제사 조각 204개를 이어 붙인 파일 |
| web/static/voice/a_{동물}.bin | 동물별 4마디 (발견, 돌진, 지침, 포획) |
| web/voice_manifest.js | 조각별 위치와 문장. 앱에 내장 |

### 관제사: 조각을 이어 붙인다

- 내비게이션 방식. "왼쪽 뒤에서 온다!" + "시속" + "사십" + "버텨!"
- 조각: 고정 문장 약 40, 방향 8 × 3형, 숫자 1~99와 100 단위, 마릿수, 동물 이름 25
- 숫자는 한글로 적어 굽는다. 모델이 "35"를 영어로 읽는 사고를 막는다
- 거리는 50m 밖이면 10m 단위로 부른다

### 다급함

- 모델 속도를 올리면 발음이 무너진다(1.35배에서 ASR 역검증 실패). 모델은 1.15배로 굽고 템포만 후처리로 1.05~1.15배
- 대사를 짧게 끊는다. "왼쪽 앞이다! 붙는다!"
- 무전기 느낌의 음색: 200Hz 이하를 깎고 2.6kHz를 4dB 올린다. 바람 소리 속에서 말이 묻히지 않는 대역이다

### 동물 목소리

- 종마다 화자, 피치, 속도가 다르다. 닭·치와와·다람쥐는 높고 빠르게, 하마·코끼리·악어는 낮게, 나무늘보는 느리게
- 피치는 0.84~1.28배 안으로. 0.7배까지 내린 하마는 ASR이 한 글자도 못 읽었다
- 적의 방향에서 들린다. 왼쪽 뒤에 있는 놈의 "꼬꼬댁! 거기 서!"는 왼쪽 뒤에서 들린다
- 나오는 때: 발견, 첫 돌진 3번, 지침 첫 2번, 포획. 그 뒤로는 울음소리만. 말 예산을 안 쓴다
- 순서: 동물이 먼저, 관제사가 이어서 방향과 속도

### 런타임

- 홈 화면이 뜨고 0.8초 뒤 팩을 미리 받는다(약 2MB). 선택한 동물 팩도 같이
- 서비스 워커가 캐시한다. 한 번 받으면 오프라인에서도 나온다
- 조각은 필요할 때 디코드한다. 전부 풀면 수십 MB라 저가 폰에서 위험하다. 방향과 급한 말은 출발 때 미리 푼다. 최근 90개만 유지
- 받는 중이면 최대 4초 기다린다. 첫 말이 기계음으로 새는 것보다 조금 늦는 게 낫다
- 더 급한 말이 오면 하던 말을 끊는다(기존 우선순위 규칙 그대로)

## 검증

### ASR 역검증

- 사람 귀 대신 한국어 음성인식(sherpa-onnx zipformer-korean)으로 되읽어 글자 오류율(CER)을 잰다
- 문장마다 후보 3개, 오류율이 높으면 5개 더. 가장 잘 읽히는 것을 고른다
- 판정은 굽고 난 최종 mp3로 한다. 원본으로 고르면 후처리에서 무너진 것을 못 거른다
- ASR 자체가 틀린다. 새로 뽑은 문장 24개를 원본 그대로 읽혀도 CER 0.19. 한 음절 조각("이", "팔")은 ASR이 거의 못 읽는다. 이 값은 절대 품질이 아니라 불량 검출용이다

| 단계 | 평균 CER (새 문장 24개) |
|---|---|
| 원본 44.1kHz | 0.188 |
| 앞뒤 무음 제거 | 0.214 |
| 템포 | 0.205 |
| 24kHz + 음량 정규화 | 0.196 |
| mp3 40kbps | 0.234 |
| mp3 64kbps (채택) | 0.210 |

### 굽기 중 잡은 결함

| 결함 | 원인 | 조치 |
|---|---|---|
| 조각 32개가 무음 | 엔진 버퍼를 복사 없이 참조. 다음 후보를 만들 때 풀림 | 복사. 최종 mp3 무음 검사 추가 |
| 큰 소리 조각이 무음 | 리미터 뒤 float64를 float32로 넘김. 길이 2배 잡음 | 형 변환 |
| "들켰다! 뛰어!"의 "뛰어" 누락 | 모델이 뒤 절반을 뭉갬. 후보 4개 모두 | "녀석들이 널 봤다. 뛰어!"로 교체 |
| "오른쪽 앞!"의 "앞" 누락 | 느낌표로 끝나는 한 단어 | "오른쪽 앞이다!"로 |

### 헤드리스 QA (web/qa.mjs)

- 팩 전 조각이 크롬에서 디코드되는가
- 대사에서 쓰는 키가 팩에 전부 있는가
- 실내 데모 완주. 브라우저 기계음 호출 0회, 동물 목소리 재생
- 팩 차단 시 브라우저 TTS로 대체
- 느린 망(팩 2.5초 지연)에서도 첫 말부터 구운 음성
- GPS 모드(위치 에뮬레이션)에서 구운 음성

## 남은 것

- 사람 귀로 듣는 확인. ASR은 알아듣는지만 본다. 다급한지, 동물답게 웃긴지는 못 본다
- 실외 이어폰 청취. 바람 속에서 무전기 음색이 충분한지
- 대사를 고치면 `python3 web/voice/bake.py` 한 번. 바뀐 줄만 다시 굽는다
