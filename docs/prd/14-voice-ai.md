# 온디바이스 AI 내레이션 검토

## 제안

앱을 켜고 동물을 고르고 출발을 누르면 폰을 주머니에 넣는다.
그때부터 온디바이스 AI(1B~2B급)가 상황을 읽고 TTS로 말해준다.
"닭이 몇 미터 뒤에 있고, 당신은 몇 킬로로 뛰고 있고, 지금 어디를 향하고 있다."

## 판정

목표는 맞다. 수단은 틀렸다. 런타임 LLM은 넣지 않는다.

이유 세 개 중 하나만 걸려도 안 되는데 셋 다 걸린다.

### 1. 안드로이드 크롬에 쓸 수 있는 온디바이스 LLM이 없다

- 크롬 내장 Gemini Nano(Prompt API)는 윈도우, 맥, 리눅스만 지원한다. 안드로이드는 미지원
- 러너웨이는 웹앱이고 플레이 배포도 TWA(크롬 껍데기)다. 안드로이드 네이티브 AI(AICore, MediaPipe)를 JS에서 못 부른다
- 남는 길은 WebGPU + WebLLM으로 모델을 직접 내려받는 것뿐이다

### 2. 직접 내려받는 길은 비용이 감당이 안 된다

| 항목 | 수치 |
|---|---|
| 모델 다운로드 | 1.5B Q4 기준 600MB~1.2GB |
| GPU 메모리 | 약 1.2GB 상주 |
| 속도 | 준수한 GPU에서 30~60 토큰/초. 저가 안드로이드 CPU는 1~2 토큰/초 |
| 안드로이드 크롬 WebGPU | 121부터 동작하나 성능이 들쭉날쭉. 업계 권고는 "데스크톱 우선 기능으로 취급" |

설치 없이 링크로 여는 게 이 앱의 강점인데, 첫 실행에 1GB를 받게 하면 그 강점이 사라진다.

### 3. 지연이 게임 규칙을 깬다

한 문장을 말하기까지

- 첫 토큰 지연 0.5~1초
- 한국어 25자면 20~30토큰. 낙관적으로 20토큰/초라도 1~1.5초
- TTS 시작 0.3초
- 합계 약 2~3초

위협 게이지는 4초면 가득 찬다. 경고가 도착할 때쯤 이미 60% 잡혀 있다.
게다가 지도를 그리는 캔버스와 LLM이 같은 GPU를 쓴다. 30분 러닝에서 발열 스로틀이 온다.

이미 정한 원칙과도 충돌한다. 발화 유통기한 8초는 "낡은 정보를 뒤늦게 말하지 않는다"는 뜻인데,
런타임 LLM은 구조적으로 낡은 정보를 만든다.

## 그러면 원하는 걸 어떻게 얻는가

원하는 건 "AI가 돌아가는 것"이 아니라 "살아 있는 목소리가 상황을 읽어주는 것"이다.
그건 런타임 AI 없이 된다. 효과가 큰 순서로 셋.

### 1순위. 목소리를 바꾼다 (실감 차이가 가장 크다)

지금은 안드로이드 기본 TTS다. 로봇 목소리다. 내용을 아무리 잘 써도 여기서 깨진다.

- 대사를 **미리 음성으로 구워서** 오디오 파일로 넣는다
- 숫자는 따로 구워 붙인다. "왼쪽 뒤" + "삼십" + "미터" 를 런타임에 이어 붙인다
- 내비게이션이 신경망 TTS 이전에 쓰던 방식이다. 자연스럽고 지연이 0이다
- 규모 추산: 고정 문장 200개 + 숫자 조각 약 60개. Opus 32kbps로 5MB 미만
- 굽는 건 빌드 때 한 번. 클라우드 TTS를 써도 1회 비용이고 운영비는 0원
- 더 싼 길: 관제사 목소리를 직접 녹음한다. 개인 프로젝트라면 이게 캐릭터가 제일 산다

### 2순위. 대사 풀을 LLM으로 미리 쓴다 (런타임이 아니라 집필 시점에)

- LLM을 내레이터가 아니라 **작가**로 쓴다
- 상황별로 대사 수백 개를 미리 생성해 앱에 박는다
- 런타임에는 그중 하나를 골라 숫자만 끼운다. 지연 0, 다운로드 0, 배터리 0
- 코드는 이미 준비돼 있다. `speak(key, variants, opts)`가 배열을 받아 돌려 쓴다. 데이터만 늘리면 된다
- 같은 말 반복으로 질리는 문제도 여기서 풀린다

### 3순위. 말할 내용을 늘린다

제안에 나온 것 중 지금 없는 것

| 내용 | 지금 | 넣을 만한가 |
|---|---|---|
| 적이 몇 미터 뒤 | 있음 | |
| 적이 어느 방향 | 있음 (다섯 방위) | |
| 적이 시속 몇 | 있음 | |
| 내 페이스 | 화면에만 | 넣는다. 러너가 실제로 행동을 바꾸는 정보다 |
| 내 진행 방향 | 없음 | 목적지가 없어 의미가 약하다. 코스 기능이 생기면 같이 |
| 구간 요약 | 없음 | 1km마다 한 줄이면 유용하다 |

## 그래도 AI를 쓸 자리

지연이 상관없는 곳이 딱 하나 있다. **주행이 끝난 뒤.**

- 30분 로그를 넘겨 한 문단짜리 경기 요약을 받는다
- 결과 카드에 같이 넣으면 공유가 는다
- 여긴 클라우드 호출이어도 된다. 달리는 중이 아니니 지연도 배터리도 문제가 아니다
- 다만 서버가 필요해 월 0원 원칙과 충돌한다. 나중에 판단한다

## 결정

- 런타임 온디바이스 LLM: 기각
- 음성 팩(미리 구운 TTS): 채택. 실감 개선의 1순위
- LLM으로 대사 미리 쓰기: 채택. 비용 0
- 페이스 안내, 구간 요약: 채택
- 주행 후 AI 요약: 보류. 서버 비용 판단 후

## 순서

이걸 지금 하지는 않는다. 앞에 걸린 게 있다.

실주행 30분 한 번이 아직 0회다. 거리 정확도, 배터리, 발열, 화면 끔이 전부 그 한 번에서 나온다.
목소리를 아무리 좋게 만들어도 값이 틀리면 좋은 목소리로 틀린 말을 하는 것이다.
